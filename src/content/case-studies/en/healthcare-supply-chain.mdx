## Problem

The platform helps hospitals track procurement spending, vendor performance, and cost savings. Each hospital organization is a tenant with its own data and reporting needs.

## Approach & alternatives considered

Clean Architecture in Go, business rules separated from infrastructure through repository interfaces, so storage engines (PostgreSQL, Elasticsearch, ClickHouse) can change without touching use cases. Concurrency with goroutines and worker pools, bulk loading and transactions for high-volume writes.

## Architecture

<Diagram />

- Client (React) → API (Go, Echo) → Org DB (PostgreSQL, one per organization)
- Async branch: Kafka → Workers
- Read branch: Elasticsearch (Insight Dashboard)
- Analytics branch: ETL → S3 → ClickHouse → Superset

## Data design

**Database-per-organization.** Each organization has its own PostgreSQL database; a request resolves its tenant first and the repository layer receives that tenant's connection. Why: hard data isolation, per-tenant backup/restore and archiving, no cross-tenant query by accident.
