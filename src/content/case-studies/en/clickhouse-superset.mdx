_Custom Report Builder lets users build their own reports by choosing the criteria they need._

## Problem

Heavy aggregation ran on each organization's PostgreSQL database, which is also the transactional system. Users wanted to choose their own report criteria over years of purchase data, and every new organization needed the same set of BI dashboards.

## Approach & alternatives considered

One source, one engine. Insight Dashboard uses Elasticsearch because its queries are predefined filtered aggregations. Custom Report Builder deliberately does **not** use Elasticsearch: arbitrary user-chosen criteria would require supporting two query modes (ES for some reports, another path for big data), doubling the code paths, the sync jobs, and the failure modes. Consolidating on ClickHouse gives a single data source and one query path for big-data reports.

Superset rollout is scripted. Dashboards, charts and datasets are cloned per organization, and across environments (production to development), for <Metric>19+</Metric> organizations instead of being rebuilt by hand. The tool rewrites dataset and database references either directly in the Superset database or by editing exported ZIP bundles. It also handles bulk deletion and reloads of embedded dashboards.

## Data design

- **PostgreSQL → ClickHouse.** The sync job reads the PostgreSQL schema, creates matching ClickHouse tables with a type mapping, exports CSV to S3, and loads it with ClickHouse's S3 table function.
- **PostgreSQL → Redshift.** The same S3 staging feeds Redshift through the Redshift Data API (`COPY` from S3).
- **Archived contracts.** Archived contract, facility and item data is pushed to S3, imported into ClickHouse, and served through year-partitioned materialized views and a Superset report.

Full loads handle the first run and backfills; incremental loads keep data current.

## Failure handling

- The sync checks that target tables exist before loading, and creates them from the source schema when they don't.
- The archive pipeline verifies each dump's row count against the live table before anything is deleted from PostgreSQL.
- Each batch job writes its own log file, so a failed run can be traced per organization.

## Security

Credentials come from AWS Secrets Manager. Jobs take the organization ID as a parameter and write only to that organization's databases, and each organization's cloned dashboards point at its own datasets.

## Trade-offs

ClickHouse is eventually consistent via batch/incremental loads, which is acceptable for reporting.

## Results

- Query time <Metric>42s → 3s</Metric> per query (over 90% faster) for reports such as Contract Spend Dashboard, Contract UOM Mismatch and VIM reports.
- Dashboards rolled out to <Metric>19+</Metric> organizations by cloning instead of rebuilding.
